# Rencana Perbaikan: ERR_MODULE_NOT_FOUND `google-auth-library` di Vercel

## Akar Masalah (hasil audit menyeluruh)

`google-auth-library` **tidak pernah di-import langsung** oleh source manapun — itu dependency transitive dari `firebase-admin` (yang sudah benar ada di `nuxt/package.json` dependencies). Jadi ini **bukan** masalah package hilang dari package.json, **bukan** masalah devDependencies, dan **bukan** masalah ESM/CJS.

Penyebab sebenarnya: **misconfiguration `nitro.externals`** di `nuxt/nuxt.config.ts`. History git membuktikan 16+ commit (`EMAIL COK 1`–`16`) yang flip-flop antara:
- `externals.trace: false`
- `nodeModules: false`
- `externals.inline: ['firebase-admin']` ← commit `f98e229` yang ter-deploy (inilah yang crash)

Saat `firebase-admin` di-inline (`externals.inline`), Nitro mem-bundle firebase-admin ke dalam chunk tetapi **meninggalkan dependency transitifnya** (`google-auth-library`, `gaxios`, `gcp-metadata`, dll.) sebagai bare external import. Saya verifikasi di committed build output `index.mjs`: `import 'google-auth-library'` muncul sebagai bare import (line 10), tetapi Vercel nft-tracer tidak menyalin paket tersebut ke runtime lambda dengan andal → `ERR_MODULE_NOT_FOUND` → `FUNCTION_INVOCATION_FAILED` → 500.

**Fix yang benar: kembalikan `nitro` ke default preset Vercel yang bersih** — biarkan Nitro melakukan externalisasi normal. Dengan preset default, Nitro menulis dependency tree lengkap (termasuk `google-auth-library 10.9.0`, `firebase-admin 13.10.0`, dll. — sudah diverifikasi ada di function `package.json`) dan Vercel meng-`npm install` semuanya untuk lambda. firebase-admin adalah dependency native-ESM yang besar; meng-inline-nya adalah anti-pattern.

Masalah kedua (kebersihan): `nuxt/.vercel/output/` (736 file, 571 muncul "modified") **sudah di-gitignore (baris 12) tapi tetap di-track git** — build rusak yang basi. Vercel rebuild dari source saat CI, jadi ini murni noise.

## File yang akan diubah

### 1. `nuxt/nuxt.config.ts` — perbaikan inti
Ganti blok `nitro` yang over-configured dengan preset default bersih.

```ts
  nitro: {
    preset: 'vercel',
  },
```

Menghapus `nodeModules: false`, `externals.external: []`. Default preset Vercel (Nitro) sudah menangani externalisasi firebase-admin + seluruh dependency tree dengan benar via file-tracing, persis seperti yang sudah diverifikasi di function `package.json` (google-auth-library, gaxios, jws, jose, fast-deep-equal, dst. semua ter-list).

### 2. Untrack `nuxt/.vercel/output/` dari git (sudah di-approve)
```bash
git rm -r --cached nuxt/.vercel/output
```
File di disk tetap utuh. `.gitignore` baris 12 (`nuxt/.vercel/output/`) sudah ada, jadi setelah untrack, git berhenti melacak 736 file ini. 571 noise "modified" hilang. Tidak ada dampak ke deploy Vercel.

### 3. Set "Root Directory = nuxt" di Vercel dashboard (sudah di-approve)
Monorepo: root = wrapper, aplikasi Nuxt di `nuxt/`. Kedua `vercel.json` (root: framework+silent; nuxt/: crons uptime) dipertahankan apa adanya. Anda set Root Directory `nuxt` di Project Settings → General di dashboard Vercel. Saya tidak menyentuh file config.

## Yang TIDAK diubah (sudah benar hasil audit)
- `nuxt/package.json` — `firebase-admin ^13.0.0` sudah di dependencies ✓, ESM (`"type": "module"`) ✓
- Semua `import 'firebase-admin/*'` — format ESM benar, konsisten di ~40 server route ✓
- `nuxt/scripts/esm-loader.mjs` & `normalize-specifier.mjs` — helper Windows ESM, tetap utuh
- `tsconfig.json`, `tailwind.config.ts`, `firebase-admin plugin` — tidak bermasalah
- **Tidak ada** dynamic-import workaround yang ditambahkan (anti-pattern, sesuai permintaan Anda)

## Verifikasi pasca-implementasi
1. `npm run build` di `nuxt/` — pastikan build sukses & generate output Vercel baru
2. Cek `nuxt/.vercel/output/functions/__fallback.func/package.json` memuat `firebase-admin` + `google-auth-library`
3. `git status` bersih (hanya perubahan `nuxt.config.ts`; noise `.vercel` hilang)
4. Push & deploy ke Vercel — `ERR_MODULE_NOT_FOUND` / `FUNCTION_INVOCATION_FAILED` / 500 tidak muncul lagi karena dependency tree lengkap di-resolve
